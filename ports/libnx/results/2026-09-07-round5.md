# 第五轮：内存映射与事件同步

新增 `Runtime/libnx/LibnxMemory.c`、`LibnxEvents.c` 和公共声明，直接调用公开 libnx API。当前作为运行时平台层组件单独验证，下一步接到 GC / PAL 接口。

## 内存方案

最初尝试 alias region 的 `svcMapPhysicalMemory`，在当前 Eden homebrew 环境返回 `64001`（`0xFA01`，Kernel `InvalidState`）。因此改用 libnx 自身创建线程时采用的方式：

1. 使用 `virtmemFindStack` 和 `virtmemAddReservation` 预留地址。
2. 提交时从 Newlib 堆分配页对齐物理页，清零后用 `svcMapMemory` 映射。
3. 回收时 `svcUnmapMemory`，再释放恢复可访问的原始堆页。
4. 提交失败时只回滚本次新增页，保留原有已提交数据。

虚拟内存操作使用 libnx 的全局虚拟内存锁。当前逐页映射，优先验证语义，尚未进行大规模内存和性能验证。页保护及可执行映射尚未验收。

测试程序使用 `size_t __nx_heap_size` 设置 128 MiB 原生堆。早期错误地使用 32 位类型覆盖该 64 位弱符号，造成初始化失败；已按 libnx 定义修正。

## 模拟器验证

```text
[AOTMEM] begin=1
[AOTMEM] memory.reserve=1
[AOTMEM] memory.repeat_commit=1
[AOTMEM] memory.bounds=1
[AOTMEM] memory.recommit_zero=1
[AOTMEM] memory.commit_rollback=1
[AOTMEM] memory.release=1
[AOTMEM] memory.checks=1
[AOTMEM] event.auto_reset=1
[AOTMEM] event.manual_reset=1
[AOTMEM] events.checks=1
[AOTMEM] pass=1
```

验证了 64 KiB 地址对齐、提交后的初始零值、重复提交不破坏数据、非法范围拒绝、回收后重新提交为零、其他页面数据保持、分配失败回滚和完整释放后的未映射状态。

分配失败通过只在测试构建启用的 `LIBNX_MEMORY_TESTING` 注入；正式构建不包含该控制入口。映射和回滚仍真实执行内核调用。

事件测试使用 libnx `UEvent`，验证超时、跨线程唤醒、自动重置和手动重置状态。关闭事件前必须结束所有等待者。

构建使用 `-Wall -Wextra -Werror`，通过。Eden 的命令、日志及 JSON 在 `artifacts/libnx/memory-probe`。没有执行完整托管运行时或 GC，也没有真机验证。
