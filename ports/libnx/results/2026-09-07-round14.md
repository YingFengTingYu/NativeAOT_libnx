# 第十四轮：基础文件 API

新增 `pal_libnx_io.c`，使用 Newlib/libnx 的公开文件接口实现当前探针需要的打开、关闭、读写、定位、长度、截断、刷新、目录创建/枚举/删除与文件删除。错误码转换改为编译上游 `pal_errno.c`，不假定 Newlib 错误码数值与 Linux 一致。

当前宿主将托管 Unix 根路径 `/` 映射到 `sdmc:/`，启动文件测试时挂载并选择 SD 工作目录。这只是本阶段的宿主约定；尚未设计游戏的 RomFS、可写存档与资源覆盖目录布局。

该工具链只有 pread/pwrite 声明，没有实现。适配层使用互斥锁保护定位、读写和恢复原位置，同时让其他 System.Native 位置修改操作使用同一把锁。不能与绕过该适配器的并发原生 stdio 共享同一个文件描述符；当前也未验证其性能。文件锁、预分配和访问提示按接口约定报告不支持，未冒充成功。

## 模拟器验证

- 中文文件名的 32768 字节写入和逐字节回读。
- FileStream 长度、绝对/相对文件尾定位、覆盖末字节及 `Flush(true)`。
- 重复创建文件触发 IOException，不存在的文件触发 FileNotFoundException。
- 目录枚举正确返回中文文件名。
- 两个 C# 线程对同一个 SafeFileHandle 各进行 64 次不同偏移读取，全部内容匹配。
- 清理测试文件和本轮子目录。
- 原生接口探针直接确认 PRead/PWrite 保留原始文件位置、截断改变长度、错误码转换正确；原有内存和条件变量回归继续通过。
- 最后通过包含移动 GC、终结器、异常、多线程、忙循环和文件 API 的完整探针。

托管验收标记为阶段 15=32768、16=1、17=2、19=128、18=1，程序返回 0。完整产物归档在 `artifacts/libnx/managed-probe/io-full-pass`，基础文件测试在 `io-basic-pass`。

本轮没有验收文件时间精度（模拟器也报告部分实现）、POSIX 权限/锁语义、跨进程共享、完整异步 I/O、游戏或真机。下一轮继续线程池与任务 API。
