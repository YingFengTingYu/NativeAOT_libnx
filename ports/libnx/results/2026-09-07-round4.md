# 第四轮：寄存器上下文与线程身份

本轮将 libnx 的 `ThreadContext` 接入 NativeAOT 的上下文表示，复用原有的寄存器访问器和上下文转换函数。其他平台继续使用原来的 `ucontext_t`，通过 `NativeContextStorage` 别名保持类型一致。

`minipal/thread.h` 新增 libnx 分支，用 `svcGetThreadId` 获取真实线程 ID，缓存行为保持不变。Horizon 没有对应的 pthread 命名操作，该可选功能明确返回 `ENOTSUP`。

展开库使用已有的 bare-metal 配置，从静态 NRO 的展开段边界获取信息，不再依赖 `dlfcn.h`。本轮仅验证其编译，不声称托管异常展开已通过。

## 模拟器验证

`build-context-probe.sh` 直接编译实际的 `NativeContext.cpp`。Eden 输出：

```text
[AOTCTX] begin=1
[AOTCTX] context.checks=1
[AOTCTX] thread.ids=1
[AOTCTX] pass=1
```

测试包括：

- PC、SP、FP、LR 和 X19–X28 转换到有限上下文。
- 修改控制寄存器及两个参数寄存器，保留未要求改动的寄存器。
- 枚举并修改 X0–X28、LR 中的 30 个潜在对象引用位置。
- 线程 ID 的缓存值与直接查询一致；主线程和工作线程 ID 非零且不同。

运行命令：

```powershell
.\ports\libnx\run-tls-probe.ps1 -Suite Context -EdenPath 'Eden v0.2.1 的 eden-cli.exe 绝对路径'
```

结果在 `artifacts/libnx/context-probe`。这些测试验证上下文数据操作，没有执行内核线程暂停、异常上下文恢复或托管 GC。完整运行时仍有 7 个 Unix 平台源文件编译失败，下一轮开始替换其内存、同步和平台操作。

修改后的 Linux x64 NativeAOT WorkstationGC 源码构建回归通过，日志为 `artifacts/log/libnx/context-host-regression.log`。
