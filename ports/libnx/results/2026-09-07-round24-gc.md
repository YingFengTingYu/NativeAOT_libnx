# 第二十四轮：GC 元数据尾页提交

实际 LawnRuntime 启动在资源加载时触发 GC，原型出现大量未映射写入。GDB 在首次访问错误停下：gc_heap::init_heap_segment 为新 region 填写 heap_segment，其 168 字节结构跨入了未提交的最后一页。

已确认的边界数据：元数据预留起点 0x1102b6e000，逻辑布局末尾 0x41a58，实际预留 0x42000。最后一个 backing block 的 committed 掩码只有 1，表示 0x41000 页未提交。heap_segment 起点为 0x1102baefd8，写入 0x1102baf000 时失败。

get_card_table_element_layout 跳过了空元素和最终长度的对齐。关闭后台 GC 时，空 mark array 的起点就是前面 segment mapping 表的未对齐末尾；get_card_table_commit_layout 又把提交上界截到这个地址所在页的起点，导致最后一页始终被排除。现在所有布局边界均按已有 alignment 表对齐，包括空 mark array 和最终长度。没有扩大 GC arena 或放宽未映射访问。

验证：重新编译 Runtime.WorkstationGC。新增托管高占用检查保留 56 个 3 MiB 数组，强制压缩 GC 后检查每 64 KiB 位置和末字节；阶段 39=56 通过。此前移动 GC、终结器、显式异常、线程、循环 GC、文件、任务、压缩、摘要和随机数整套回归同时通过，日志没有 HW.Memory 错误。

实际游戏随后完成加载并呈现包含 Logo 和“点击开始”的标题界面，累计绘制 534 帧。退出保存用户列表仍失败并出现空地址读取，因此完整启动/退出探针仍判失败，不能将 GC 修复写成完整客户端已经完成。

首次失败与 GDB 记录：artifacts/libnx/game-boot/round24-init-fault。验证脚本和托管测试位于游戏仓库 experiments/nativeaot-libnx。硬件隐式空引用、真机、输入、音频和长期 GPU 稳定性仍未验证。
